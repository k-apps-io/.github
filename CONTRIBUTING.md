# Contributing

Thanks for helping maintain governance standards for `@k-apps-io`.

## Before You Start

- Confirm the change is linked to an issue with clear acceptance criteria.
- Keep pull requests focused on one governance concern.
- Avoid mixing unrelated refactors or formatting-only churn.

## Pull Request Requirements

- Use the default pull request template.
- Describe scope, validation steps, and risk/rollback notes.
- Ensure required CI checks pass.
- Request review from listed code owners.

## Standards

- Prefer clear, deterministic language in policies and templates.
- Keep examples actionable and repository-agnostic unless explicitly scoped.
- Preserve backward compatibility where possible for org-wide defaults.

## Out of Scope

- Repo-specific implementation details that belong in individual repositories.
- Emergency security disclosures (follow `SECURITY.md` instead).
